# Measured capacity release

Target: 1,001 businesses, 350 simultaneous voice sessions, and 200 inbound SMS events/second together. This source update does not certify that throughput. No provider traffic, infrastructure purchase, migration, deployment, or remote Git write is performed by the installer.

## What changed

- Deployment rendering requires a capacity-plan file tied to the exact API SHA, with recent normal and slow-provider processing measurements. It sizes SMS replicas from the slower p95, 25 lanes, declared utilization (maximum 80%), and one spare. It rejects undersized overrides, insufficient Mongo connection allocation, insufficient voice N-1 capacity, and combined provider RPM/TPM/SMS-segment/concurrency budgets. Voice and SMS must share the account budget; other workers have explicit reserve fields. Autoscaling uses maximum replicas plus rollout allowance in concurrency/connection budgeting. Provider quotas are declarations that must be backed by real account evidence.
- With 200 jobs/s, a measured 2,000 ms p95 and 65% utilization, the formula produces 26 SMS replicas. That configuration allocates 1,380 Mongo pool connections including deployment surge and operator reserve. It requires at least 1,075 concurrent AI slots including the voice turn cap and SMS rollout lanes, plus any other-worker reserve. These are conservative allocation calculations, not measured throughput or a claim that a provider offers a universal concurrency setting. Account RPM/TPM and model-specific limits still apply.
- Owner workflow summaries are shared across tabs and searches. Only active leads enter workflow joins; historical booked/lost counts are retained. Search-specific counts are cached separately. This reduces repeated work while retaining authoritative reads and existing response shapes. It does not replace contains-search with different matching behavior or pretend substring searches are constant-time. Active histories and search scans still require measurement.
- Query probes explain the actual status/workflow summary pipelines in addition to history/search paths. Mixed HTTP traffic covers ready/waiting/needs-me lists as well as normal and no-match searches. The certificate requires typical and 100,000-lead tenant query evidence; a query timeout is a failed gate.
- Every fleet heartbeat records its release, image digest, and capacity-plan hash. Mixed-load runs sample fleet health during the timed interval, excluding setup and drain from credited soak time. Certificate checks require queue age within budget throughout the recorded intervals, explicit zero failure counters, complete sampling, and matching fleet identity.
- Evidence schema 2 checks file hashes, release identities, freshness, non-overlapping cohorts, and real-provider mode. Simulated measurements are useful for staging sizing but cannot certify live-provider capacity. Manual observations require attached files and exact API/UI identities. A reviewer must verify their truth; checksums are integrity checks, not signatures or independent proof.

## Install / local verification

Use the bundle's `install.mjs --check`, then `--apply`, then `bash verify-local.sh`. The installer verifies all source-file hashes before writing, makes backups, and refuses conflicts. `--rollback <backup-path>` only restores files that still match the installed version. It does not edit .env.

The default verifier runs targeted unit, persistence and fleet suites, index-manifest validation, and the build. Run `bash verify-local.sh --full` to also run the repository's complete `release:certify:ci`. Any failure stops the verifier. A local Mongo startup restriction is a blocked test, not a passing persistence test.

## Required runtime migration

Normal deployments without SCALE_PROFILE retain their existing runtime configuration behavior. Deployments using `business-1000-voice-350` must regenerate their configuration with a measured capacity plan before adopting this release. The stricter profile intentionally rejects the old unmeasured configuration. Publish all application roles from the same immutable image; a mixed old/new fleet cannot pass acceptance. Configuration generated by the renderer takes precedence over colliding keys in the runtime secret.

The new heartbeat fields require no index migration. Existing required indexes still must be verified against the real deployment. Back up the target database and select its MONGO_URL explicitly before running the existing additive index migration. No index is dropped by this update.

## Staging sequence

1. Commit the installed API changes locally after all local gates pass. Record that exact SHA and the frontend SHA actually deployed. No frontend code changes are required by this bundle.
2. Fix GitHub Billing & plans if jobs cannot start, then rerun API CI, Security and customer/staff browser workflows. Run `npm run verify:release-ci` with RELEASE_SHA and GH_TOKEN for a private repo. That command is read-only and fails when checks are missing, failed, or still running. A local pass or Dependabot run is not a replacement for these checks.
3. Measure whole-job SMS processing on the same source in an isolated staging configuration, including normal and slow-provider behavior. Use at least 1,000 completed jobs and five minutes per scenario. Use traces/worker timing observations, not HTTP ACK latency; account for retry attempts, prompts, token use, model calls, and SMS segments. The existing non-scale runtime can bootstrap these measurements; do not label that initial run certified scale. Increasing replicas is not a substitute for provider and database capacity.
4. Copy `deploy/scale/capacity-plan.example.json` to an untracked capacity-plan.json and populate real observations and references. The sample zeros deliberately fail. Use providerMode=simulated when any provider boundary is mocked. Obtain actual per-model RPM/TPM, Twilio segment/voice limits and account budget evidence; include other AI jobs in the reserve. Provider budgets must cover combined SMS+voice+other demand at the chosen utilization. Derive concurrency from measured requests and account limits; do not invent it.
5. Render with SCALE_CAPACITY_PLAN, SCALE_IMAGE (immutable digest), RELEASE_SHA, SCALE_MONGO_CONNECTION_BUDGET, SCALE_INGRESS_HOST, and SCALE_TLS_SECRET. Existing runtime secrets, Mongo replica set, Redis, ingress, TLS and paging remain required. Review the generated topology and host resources before deploying. Optional HPA still requires a working external metrics adapter. Nothing here provisions the cluster.
6. Populate dedicated staging tenants using authorized provider destinations. Each tenant requires at least 1,000 leads and 21+ customer messages for the existing harness. Include at least one 100,000-lead tenant with representative active/historical proportions. Do not buy numbers merely to seed tests. Mock provider tests must remain labeled simulated; real-provider evidence is separate. Preserve production anti-abuse and subscription policies; any special fixture allowances must be isolated to test tenants.
7. Run `npm run probe:scale-queries` for a typical and a large-history tenant using SCALE_PROBE_BUSINESS_ID, SCALE_PROBE_LEAD_ID, RELEASE_SHA, MONGO_URL and separate SCALE_QUERY_REPORT paths. Inspect examined keys/documents, lookup scans and elapsed time. Existing contains search may need a dedicated search/read model if measured SLOs fail. Do not raise timeouts or weaken the certificate to mask an overloaded route.
8. Set SCALE_API_SHA, SCALE_UI_SHA, SCALE_CAPACITY_PLAN_SHA256, SCALE_IMAGE_DIGEST and SCALE_PROVIDER_MODE to the actual deployment identities, plus the existing authenticated tenant manifest, admin token, voice/signature and staging authorization settings. The plan hash is printed by the renderer and written to its ConfigMap. Run `npm run perf:mixed-soak`. Every cohort must pass: dashboard p95 <=1s, expensive reads p95 <=1.5s/p99 <=3s, SMS ACK p95 <=0.5s/p99 <=1s, persisted provider acceptance p95 <=10s, sampled oldest SMS work <=10s, recovery <=30s, and no failed/uncertain notifications during baseline. These bounds include in-flight work; a queue-age breach is a failed baseline.
9. Separately exercise noisy tenants, worker death, voice graceful/abrupt loss, Redis outage, Mongo failover, provider 429/timeouts, replay, customer/staff notifications and no-response escalation. Preserve recovery and no-duplicate evidence. An abruptly lost voice socket cannot migrate; verify the configured customer recovery path. Also obtain the continuous live-provider soak, real phones, mobile login, calendar, billing and backup-restore observations required by the certificate.
10. Assemble evidence with `npm run prepare:scale-evidence -- /absolute/path/to/input.json`. Input keys: apiSha, uiSha, capacityPlan (file path), imageDigest, topology (file path), mixedReports (paths), queryReports (paths), checks. Each checks entry needs passed, observedAt, observedBy, apiSha, uiSha, file. This copies attachments, computes hashes, and leaves unspecified observations unpassed. It refuses an existing output directory. Run `SCALE_EVIDENCE_DIR=<output> npm run verify:scale-certificate`, then have the referenced evidence reviewed before approving traffic.

## Remaining external prerequisites

GitHub account billing, provider quota increases, actual infrastructure capacity, database-backed release tests, load measurements, failover exercises and operator observations cannot be produced by installing source files. This update intentionally fails approval until those requirements are supplied. It makes no numeric capacity guarantee in their absence.
